# Запуск AutoHistory на этом компьютере

Первичная настройка создаёт отдельный PostgreSQL-кластер в `.local/postgres`, базу `autohistory` и применяет миграции. Подключение доступно только на `127.0.0.1:55432`; существующие установки и базы PostgreSQL не изменяются. Docker и VPS не нужны.

## Запуск и остановка

1. Токен Telegram хранится в `.env`, в строке `BOT_TOKEN`. После изменения сохраните файл. `.env` и `.local` исключены из Git. Никому не пересылайте эти файлы.
2. Дважды щёлкните **«Запустить бота.cmd»** в корне проекта. Окно должно сообщить имя бота и оставаться открытым. Не запускайте второго бота с тем же токеном на другом компьютере или сервере.
3. Откройте бота в Telegram и отправьте `/start`. Выберите часовой пояс и добавьте автомобиль.
4. Для остановки используйте **«Остановить бота.cmd»**. Если запускали в видимом окне, можно нажать Ctrl+C или закрыть его. Дочерние процессы бота и напоминаний завершатся; база и сохранённые данные останутся на диске.

Первый запуск помощником может быть выполнен в фоне без отдельного окна. В этом случае остановка также доступна через «Остановить бота.cmd». После перезагрузки компьютера запускайте «Запустить бота.cmd» снова: автозапуск в Windows не установлен.

Бот отвечает, пока компьютер включён, не спит и имеет доступ к Telegram. Режим сна останавливает работу. Можно выключать монитор, оставляя компьютер работать. Локальный запуск проверяет напоминания раз в минуту; установка cron или планировщика Windows для этого режима не нужна. На VPS используются прежние точки входа и cron из README.

## Где находятся данные

- `.env` — токен и пароль локальной базы.
- `.local/postgres` — постоянная база данных. Не удаляйте эту папку и не копируйте её во время работы PostgreSQL как замену pg_dump.
- `.local/logs/bot-ГГГГ-ММ-ДД.log` — работа бота и ошибки.
- `.local/logs/reminders-ГГГГ-ММ-ДД.log` — проверка напоминаний.
- `.local/postgres.log` и `.local/setup.log` — запуск локальной БД.
- `tmp/deletions` — журнал удаления объектов для восстановления из старого дампа.

Перед хранением важных реальных данных настройте резервные копии на другой носитель. База на одном компьютере не является резервной копией.

## Подключение pgAdmin (необязательно)

Чтобы посмотреть данные, в pgAdmin выберите Register → Server:

- Name: `AutoHistory Local`.
- Host: `127.0.0.1`.
- Port: `55432`.
- Maintenance database: `autohistory`.
- Username: `autohistory`.
- Password: значение `POSTGRES_PASSWORD` из `.env`.

Создавать таблицы вручную не нужно. Если изменить пароль только в `.env`, пароль уже созданного пользователя БД сам не изменится.

## Диагностика

Из PowerShell в папке проекта:

```powershell
.venv\Scripts\python -X utf8 -m app.local --prepare
.venv\Scripts\python -X utf8 -m app.local --check
```

Первая команда проверяет БД и миграции, вторая дополнительно проверяет токен через Telegram getMe, не отправляя сообщений пользователям. Токен в вывод не попадает. Ошибка о включённом webhook означает, что этот токен уже используется другим способом; локальный polling нельзя включать одновременно с ним.

Для остановки только отдельного сервера базы после остановки бота:

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe' -D .local/postgres -m fast -w stop
```

Следующий запуск бота автоматически запустит эту базу снова.
